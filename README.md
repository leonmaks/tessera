# Logseq TypeScript Parity — Codex Implementation Package

This repository is a **specification-first implementation scaffold** for building a TypeScript system that reproduces Logseq behavior without translating the upstream ClojureScript source line-by-line.

## What is included

- `AGENTS.md` — non-negotiable rules for Codex.
- `openspec/config.yaml` — project context injected into OpenSpec work.
- `openspec/specs/*` — baseline product/behavior contracts.
- `docs/adr/*` — architecture decisions.
- `docs/IMPLEMENTATION-ROADMAP.md` — phase order and exit criteria.
- `packages/*` — TypeScript domain contracts and package boundaries.
- `packages/graph-db/src/schema.sql` — initial SQLite/EAV schema.
- `tests/bdd/*` — Gherkin behavior contract.
- `tests/property/*` — invariant/property-test starting point.
- `tests/parity/*` — differential testing/oracle contract.
- `codex/START.md` — exact Codex workflow.
- `codex/MASTER-PROMPT.md` — one paste-ready instruction to start Codex.
- `scripts/*` — baseline pinning and architectural checks.

## First run

### PowerShell

```powershell
corepack enable
pnpm install
pnpm bootstrap
```

### Bash

```bash
corepack enable
pnpm install
pnpm bootstrap
```

`pnpm bootstrap` validates the project, refreshes OpenSpec integration for Codex when possible, and attempts to pin the current upstream Logseq commit. If upstream is unavailable, the package remains usable; pin it later with:

```bash
pnpm baseline:pin
```

## Start Codex

Open the repository in Codex and follow `codex/START.md`.

For OpenSpec in Codex, use the generated skills, e.g.:

```text
$openspec-propose
$openspec-apply-change
$openspec-sync-specs
$openspec-archive-change
```

The exact installed skill names are generated by OpenSpec and should be treated as authoritative.

## Definition of parity

A feature is complete only when:

1. its OpenSpec requirement is satisfied;
2. its Gherkin scenarios pass;
3. unit/TDD tests pass;
4. graph invariants pass under `fast-check`;
5. compatibility fixtures match normalized upstream behavior;
6. no architecture boundary is violated.

## Upstream policy

This project may inspect Logseq to determine behavior and contracts, but implementation code MUST be independently written in TypeScript. Do not paste or transliterate upstream functions. See `docs/UPSTREAM-POLICY.md`.
